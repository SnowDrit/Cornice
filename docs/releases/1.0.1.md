### Added

- An explanation with an **Open Accessibility settings** button when a menu bar action on macOS 27 needs access that Cornice does not have. Cornice explains why it cannot hide icons; revealing remains available. After granting access, repeat the click or shortcut to hide icons.

### Fixed

- Clicking the chevron, ⌥-clicking it, or using a shortcut for either group no longer fails silently when Accessibility is missing. This can happen after updating an ad-hoc signed build, even if Cornice still appears enabled in the Accessibility list.

### Changed

- Missing access is detected automatically, but the explanation appears only after an explicit action. Startup and background checks do not open permission prompts.
- Installation guidance explains how to renew a stale Accessibility entry: open System Settings > Privacy & Security > Accessibility, remove the old Cornice entry, add the current app from Applications, and enable it. This changes only the access entry; it does not remove Cornice, its settings, or divider positions.

Some bugs may remain, especially on macOS 27. If you notice unexpected behavior,
please [report it in Issues](https://github.com/SnowDrit/Cornice/issues) with your
macOS version and the steps to reproduce it. See the [macOS 27 notes](https://github.com/SnowDrit/Cornice#macos-27)
for current visibility limitations.

**Install:** download `Cornice.dmg` below, drag it onto Applications.
The build is ad-hoc signed and not notarised. If macOS blocks the first launch,
follow [Apple's instructions](https://support.apple.com/en-us/102445) to approve
Cornice in System Settings > Privacy & Security after trying to open it.

Requires macOS 26 (Tahoe) or later, Apple Silicon.
